# 交付前检查清单

逐项确认，未通过的项要么修正，要么写进交付说明的“需要你处理的事项”。

## 一致性

- [ ] 软件全称、版本号在说明书封面、说明书页眉、源代码页眉、采集卡中完全一致。
- [ ] 说明书、源代码文档、采集卡取自同一代码基线（分支、提交已记录）。
- [ ] 说明书“系统运行要求”与采集卡各环境字段一致。
- [ ] 采集卡“源程序量”与 `source_code_docx.py stats` 的结果一致，只含自研代码。
- [ ] 采集卡“主要功能”的每一条都能在说明书和代码中找到。

## 说明书

- [ ] `check_ruanzhu.py design` 无 ERROR；每个 WARN 已判断并处理或说明。
- [ ] 每个功能章节至少一张流程图；总体结构图和运行流程图齐全。
- [ ] 页数满足源程序量对应的最少页数；无图页面不少于 30 行。
- [ ] 目录页码已回填，交付时提醒在 Word 中更新目录。
- [ ] 正文中没有“待确认”“TODO”、网址、公司名、第一人称。
- [ ] 每个数字都能在代码中找到出处；措辞不超出代码证明的范围。
- [ ] 封面没有空白字段和多余的项目符号；修订记录与实际一致。
- [ ] 逐页看过预览：图文清楚、图题与图同页、标题没有意外折行。

## 源代码文档

- [ ] `check_ruanzhu.py source` 无 ERROR。
- [ ] 60 页（或不足 60 页时全部），每页不少于 50 行。
- [ ] 首页从文件开头开始，末页以完整结尾结束。
- [ ] 没有第三方库、自动生成文件；没有删除他人版权声明后收录的文件。
- [ ] 可疑行（网址、邮箱、版权、公司名）已处理。

## 信息采集卡

- [ ] `check_ruanzhu.py card` 无 ERROR。
- [ ] 申请人信息、日期、发表情况没有替用户编造；未知项为红色【待填】。
- [ ] 输出的 Word 采集卡渲染检查过；Markdown 版已一并交付。

## 交接

- [ ] 待确认事项（代码中无法确认的逻辑）已列出。
- [ ] 需要申请人提供或处理的事项已列出：【待填】字段、截图、营业执照、签章与手抄承诺、合同。
- [ ] 已提醒 AI 承诺问题（见 registration-rules.md 第 4 节）。
- [ ] 已说明规则以代理机构和版权中心的最新要求为准，本技能产出为草稿。
