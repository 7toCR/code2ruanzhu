# 说明书的结构与写法

先读参考软著（`pandoc -t markdown 参考.docx`），并渲染几页看版式，确认它的章节骨架和句式；用户另有目标模板时，以目标模板为准。下面两种版式都已验证可用。

## 1. 选版式

| 版式 | 特点 | 何时用 |
|---|---|---|
| 参考版式（`NUMBERED = False`） | 封面三行进入目录；“一：软件概述”“二：系统运行要求”居中；功能章节为左对齐二级标题；图下不加图题，正文用“详情如下图所示：” | 用户给的参考软著就是这种样式，或代理要求照参考件排 |
| 编号版式（`NUMBERED = True`） | 1 / 3.1 / 4.1.1 三级编号；每张图下有“图 3-1 标题”；正文用“详情如图3-1所示。”；目录三级 | 没有参考件，或模块多、需要按图号相互引用；本技能自带模板即此版式 |

## 2. 章节骨架

编号版式推荐的章节（参考版式把前两章写成“一：”“二：”，其余为平级功能章节）：

1. **软件概述**：第一段写运行平台、主要功能、实现方式和本说明书的用途；第二段概述架构分层，结尾用固定句式“下面通过A、B、C……等内容，对<软件全称>进行逐一的阐述介绍。”
2. **系统运行要求**：条目式。通用条目为硬件环境、软件环境、通信接口、开发环境；嵌入式软件再补充处理器与主频、操作系统与协议栈、通信参数、外部设备；PC 或 Web 软件写服务器和客户端的操作系统、CPU、内存、硬盘、浏览器、数据库。目标模板里已有的条目原样保留，只在后面补充。这些内容要与采集卡的环境字段一致。
3. **软件总体设计**：总体结构（图）、运行流程（图）、初始化（视需要，图）。
4. **软件模块详细设计**：按数据流排序，每个模块一节，每节至少一张图。例如：下行或输入处理 → 控制执行 → 各条通信链路 → 状态上报 → 电源、采集等辅助模块 → 固件升级。
5. **接口与数据结构**（可选）：协议帧格式、功能码、报文、数据库表，用表格写。
6. **运行与部署**（可选）：编译、烧录或安装、启动、与上位机或浏览器连接的步骤。

按用户的规则文件补充“引言（编写目的、项目背景）”“需求分析”等章节时，内容也必须来自代码或用户提供的资料，不写空话。

## 3. 每章写法

1. 首段：“XX模块（文件名.c）负责……。”然后按执行顺序叙述处理过程，带上关键参数（周期、长度、ID、阈值），以“详情如图3-1所示。”（参考版式为“详情如下图所示：”）结尾。content.py 里写 `{图:key}`，脚本按版式自动替换。
2. 流程图：居中。编号版式下方自动加图题。
3. 后续段落可选用以下一种或两种：
   - 用“其中，……”或“同时，……”说明同一模块的另一个执行单元，再接子图。
   - 用“具体字段解释如下：”接项目符号，每条写成“名称：说明。”，适合帧格式、功能码、报文、引脚、状态变量等；条目多、有多列时改用表格。

## 4. 语言

- 主语用“软件”，不用“我们”“本人”，不写宣传性语句。
- 函数名可以用括号注出，每段不超过两三个；写真实全名，长名可首次出现时注明“下文简称”。
- 数字都带单位。中文与英文、数字之间不加空格，例如“STM32F407主控板”“CAN FD总线”。
- 不出现网址、邮箱、公司名称，不出现“待确认”“TODO”“推测”等字样。
- 措辞强度不超过代码能证明的范围，见 code-facts.md 第 4 节。
- 每章 2~4 段为宜。

## 5. 篇幅与版面

- 页数按源程序量定：1 万行以下 15 页以上，1 万行以上 20 页以上，10 万行以上 40 页以上。约 15 张图的设计说明书一般 25~45 页。
- 文档每页不少于 30 行（有图的页除外）。只在封面后、目录后分页，章节之间不强制分页，否则会出现只有十几行的页面。
- 图高不超过约 21 cm；图放不下被推到下一页时，前一页会留下大片空白，可缩短图、拆图或调整前后段落。

## 6. 软件说明书（用户手册，仅在用户提供截图时制作）

- 截图只能由用户提供。不得自己截图、伪造界面，也不得用流程图代替截图。没有截图时只交设计说明书，并列出需要哪些界面的截图。
- 封面第三行沿用参考文档的叫法，例如“用户手册”或“软件说明书”。
- 截图必须来自要登记的这个软件，且平台一致（电脑与手机、安卓与 iOS 不混用）。上位机工具的截图不能拿来充当嵌入式固件的操作界面。
- 逐张用 Read 查看截图，只描述图上看得见的菜单、按钮和字段。能读到相应代码时，用代码核对字段含义。
- 每个界面一节，按下面的顺序写：
  1. “操作人员可以通过该功能进行XX的操作处理，操作人员在该操作界面上……，点击界面上的按钮进行处理操作。详情如下图所示：”
  2. 截图（FIG 第三项写 `'shot'`）。
  3. “操作人员在该操作界面上输入数据信息参数进行设置操作，包括：【字段1】、【字段2】等信息参数……”
  4. 需要时接“具体字段解释如下：”和项目符号。
- 截图按文件名分组排序（如“下行1”“下行2”）。文件名看不出对应功能时，问用户。
