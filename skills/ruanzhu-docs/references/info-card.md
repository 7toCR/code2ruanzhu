# 信息采集卡（申请表信息）

采集卡是代理机构用来收集申请表内容的表格，字段与版权中心的在线申请表一一对应。你能起草的是**技术字段**；涉及申请人身份、日期和发表情况的字段只能由申请人提供。

## 1. 字段与来源

| 字段 | 来源 | 写法要点 |
|---|---|---|
| 软件名称、版本号 | 用户/说明书页眉 | 与说明书、源代码页眉完全一致；名称以“软件/系统/平台”结尾；版本号写 V1.0 形式，与代码中的版本宏不矛盾 |
| 软件简称 | 可空 | 不确定就留空，不写“无” |
| 软件分类 | 判断 | 运行在 MCU/设备上的固件选“嵌入式软件” |
| 软件作品说明 | 用户 | 默认“原创”；“修改”需原权利人授权 |
| 开发完成日期 | **用户确认** | 可参考代码基线的最后提交日期，但以真实完成日期为准；须晚于公司成立日期（代理通常要求半年以上） |
| 发表状态、首次发表日期与地点 | **用户确认** | 发表指销售、赠送、产品发布、网上发布、为销售而展示等向公众提供；发表日期须晚于开发完成日期且不能同一天。不知道就标【待填】，不替用户选 |
| 开发方式 | 用户 | 默认“独立开发”；合作、委托、下达任务需对应合同或任务书 |
| 著作权人（名称、证件类型、证件号码、省份/城市） | **用户提供** | 企业证件类型为营业执照，证件号码为 18 位统一社会信用代码；只能照用户给的信息填，不能搜索或推测 |
| 权利取得方式、权利范围 | 用户 | 默认“原始取得”“全部” |
| 开发的硬件环境 | 代码工程 + 用户 | 开发电脑配置、调试器、目标板；电脑配置不清楚时写最低要求或标【待填】 |
| 运行的硬件环境 | 代码 | 芯片型号（从工程文件读取）、主频、Flash，主要外设 |
| 开发该软件的操作系统 | 工程文件 + 用户 | 从工具链路径等推断平台（如 Keil 装在 D 盘 → Windows）；具体版本不确定时写范围或标【待填】 |
| 软件开发环境/开发工具 | 工程文件 | IDE、编译器及版本、配置工具及版本（如 .uvprojx、.ioc、package.json 中读取） |
| 运行平台/操作系统 | 代码 | 例如“STM32F407 微控制器，FreeRTOS V10.6.2” |
| 运行支撑环境/支持软件 | 代码 | HAL 库、RTOS 接口、协议栈、数据库、运行时等 |
| 编程语言 | 代码 | 按实际代码语言填写，不填开发工具 |
| 源程序量 | `source_code_docx.py stats` | 自研代码总行数，与源代码文档用同一组文件 |
| 开发目的 | 说明书 | 一句话，建议 50 字以内 |
| 面向领域/行业 | 判断 | 建议 30 字以内 |
| 软件的主要功能 | 说明书 | **500–1300 字**（2026 年新版申请表）；按说明书的模块逐条写功能、实现逻辑、关键参数和应用场景，每条都能在代码中找到；不写空话 |
| 软件的技术特点 | 说明书 | 建议 100 字以内；写实际采用的技术手段 |

各字段的字数上限以申请系统实际限制为准；不确定时宁可写短。

## 2. JSON 格式

完整示例见 `assets/example/info_card.json`。键名就是上表的字段名，著作权人为列表（可多个）。未知信息一律写成 `【待填：……】`，脚本会把它标红。

```json
{
 "软件名称": "XX嵌入式软件", "版本号": "V1.0", "软件简称": "", "软件分类": "嵌入式软件",
 "软件作品说明": "原创", "开发完成日期": "【待填：真实开发完成日期】",
 "发表状态": "未发表", "首次发表日期": "", "首次发表地点": "", "开发方式": "独立开发",
 "著作权人": [{"姓名或名称": "【待填】", "证件类型": "营业执照", "证件号码": "【待填】", "省份/城市": "【待填】"}],
 "权利取得方式": "原始取得", "权利范围": "全部",
 "开发的硬件环境": "……", "运行的硬件环境": "……", "开发该软件的操作系统": "……",
 "软件开发环境/开发工具": "……", "该软件的运行平台/操作系统": "……", "软件运行支撑环境/支持软件": "……",
 "编程语言": "C", "源程序量": 12000, "开发目的": "……", "面向领域/行业": "……",
 "软件的主要功能": "……（500–1300 字）", "软件的技术特点": "……",
 "公司成立日期": "（可选，只用于检查日期间隔，不写入采集卡）"
}
```

## 3. 填写与检查

```bash
python3 <skill>/scripts/check_ruanzhu.py card 采集卡.json --design 说明书.docx --stats out/源代码统计.json
python3 <skill>/scripts/fill_info_card.py 采集卡模板.doc 采集卡.json -o out/<全称>_信息采集卡.doc
```

- 用户给了代理机构的采集卡模板（.doc/.docx）就填那份；没有时用 `assets/template_info_card.docx`。原模板不改动，输出另存。
- 脚本按“标签单元格”定位字段，写入右侧或下方的单元格；选择题用 ⊙/○ 标记；发表状态同时写入日期和地点（未发表时清空提示文字）。它会列出每个字段写到了哪个单元格、哪些字段在模板中没找到、模板中残留的“*必须填写”等提示。
- 同时输出 `<输出名>_填写内容.md`（含各字段字数），没有 LibreOffice UNO 环境时至少交这一份，便于用户对照在线申请表逐项粘贴。
- 渲染成 PDF 看一遍：选中项、换行、红色【待填】都要正确。
- 交付时列出所有【待填】项，说明每项需要什么信息、为什么只能由申请人提供。
