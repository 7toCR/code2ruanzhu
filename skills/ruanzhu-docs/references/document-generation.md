# 生成说明书 .docx：content.py 与 build_docx.py

## 1. 选模板

按优先级：

1. 用户给的**目标模板**（已建好封面、页眉、修订记录的文档）：保留它目录之前的全部内容（封面、封面表格、修订历史），以及页眉页脚、页面设置和样式；目录和之后的旧正文全部重写。
2. **参考软著**本身：同上，并用 `HEADER_REPLACE` 把页眉里的旧软件名换成新名称。
3. 都没有时，用本技能自带的 `assets/template_design.docx`（编号版式；页眉为“【软件全称】 【版本号】”加右侧页码，生成时自动替换）。

模板的封面标题段按以下规则识别：目录之前有不少于 N 个一级标题段时取前 N 个，否则取目录之前前 N 个非空段（含封面框表格里的段落）。N 是 `TITLE` 的行数，所以 `TITLE` 的行数要和模板封面的标题行数一致（例如模板封面是“软件全称 V1.0”和“详细设计说明书”两行时，`TITLE` 也写两行）。

## 2. content.py

完整示例见 `assets/example/content.py`。

```python
TITLE = ['XX嵌入式软件', 'V1.0', '详细设计说明书']   # 封面各行
NUMBERED = True                                      # 编号版式；参考版式写 False
FIG = {
    '00': ('flowcharts/00_软件总体结构.png', '软件总体结构图'),   # 第二项：编号版式的图题 / 图片替代文字
    's1': ('shots/下行1.png', '下行控制界面', 'shot'),            # 截图：第三项写 'shot'
}
HEADER_REPLACE = []                 # 用参考软著当模板时填 [('参考软件全称', '本软件全称')]
COVER_FIELDS = {'作者': '……'}       # 可选：模板封面表格“作者:”等右侧空格；只填申请人确认过的真实信息
BLOCKS = [
    ('pb',),                                   # 分页（自带模板的封面后已分页，此处让正文从目录后新起一页）
    ('h1', '软件概述'),                        # 编号版式：h1/h2/h3；参考版式：('h2c', '一：软件概述')、('h2', '功能章节')
    ('p', '本软件运行于……'),
    ('h1', '系统运行要求'),
    ('req', '硬件环境：……'),
    ('h1', '软件总体设计'),
    ('h2', '软件总体结构'),
    ('p', '……详情如{图:00}所示。'),            # {图:key} → 编号版式“图3-1”，参考版式“下图”
    ('fig', '00'),
    ('fields', '具体字段解释如下：', [('上位机通信层：', '包括……')]),
    ('table', [['功能码', '名称', '说明'], ['0x01', '查询版本', '……']], {'widths': [2, 3, 9.6]}),
    ('p', '……', 'keep'),                       # 'keep'：与下一段同页
]
```

- 每张图在 BLOCKS 中只插入一次；FIG 中没被使用的图会给出警告。
- `{图:key}` 引用了不存在或未插入的图时，脚本直接报错。
- 表格第一行为表头（加粗、浅灰底、跨页重复）；`widths` 单位为厘米，可省略。

## 3. 生成与目检

```bash
python3 <skill>/scripts/build_docx.py --content content.py --out out/<全称>_详细设计说明书.docx --auto-toc [--template 模板.docx]
python3 <skill>/scripts/check_ruanzhu.py design out/<全称>_详细设计说明书.docx --name <全称> --version V1.0 --code-lines <源程序量> --pdf out/pdf/<全称>_详细设计说明书.pdf
```

- **样式**：脚本自动识别模板的 heading 1/2/3、TOC 1/2/3、TOC Heading、Hyperlink 和项目符号编号。正文为宋体小四、1.5 倍行距、首行缩进 2 字符，可在 content.py 的 `STYLE` 里改 `font` 和 `sz`（半磅）。
- **编号**：模板的标题样式自带多级编号时，标题文字不加编号；否则脚本在标题前加“3.1 ”这样的文字编号。目录条目始终带编号。
- **目录页码**：`--auto-toc` 用 LibreOffice 渲染 PDF，查出各标题所在页并回填目录，反复执行直到页码稳定。PDF 在输出目录的 `pdf/` 子目录下。Word 与 LibreOffice 的分页可能差一两页，交付时提醒用户在 Word 中右键目录 → 更新域 → 更新整个目录。
- **封面**：封面标题段上的项目符号或编号会被去掉；编号版式下封面行不进入目录。
- **图片**：流程图按正文宽度插入，但不超过原始尺寸（小图不放大），过高时按 21.5 cm（编号版式 20.5 cm）限高；缩到 2/3 并量化为 256 色以控制文件体积。截图不量化。
- **目检**：用 `pdftoppm -r 60` 生成缩略图并拼起来看，覆盖封面、目录、正文和几张大图页。标题不能意外折行，目录不能变成斜体，图里的文字要看得清，图题与图在同一页。

## 4. 写回用户文件

- 写回用户目录前，若目标文件已存在，先复制为同目录下的 `<原名>_原版备份.docx`；写回前用 md5 确认原文件在你工作期间没有被改动。
- 目录里有 `~$` 开头的 Word 锁文件时，提醒用户关闭文档后再重新打开。
- 交付文件夹里只保留一份定稿；草稿、旧版本和模板副本放到子目录或删除前先问用户，避免提交错版本。
