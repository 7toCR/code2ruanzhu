# 生成说明书 .docx：content.py 与 build_docx.py

## 1. 选模板

按优先级：

1. 用户给的**目标模板**（已建好封面、页眉、修订记录的文档）：保留它目录之前的全部内容（封面、封面表格、修订历史），以及页眉页脚、页面设置和样式；目录和之后的旧正文全部重写。
2. **参考软著**本身：同上，并用 `HEADER_REPLACE` 把页眉里的旧软件名换成新名称。
3. 都没有时，用本技能自带的 `assets/template_design.docx`（编号版式；页眉为“【软件全称】 【版本号】”加右侧页码，生成时自动替换）。

有已获批的参考软著时，不论用哪个模板，都加 `--like 参考软著.docx`（或在 content.py 里写 `LIKE = '参考软著.docx'`），让各类段落照参考件排，见第 6 节。

模板的封面标题段按以下规则识别：目录之前有不少于 N 个一级标题段时取前 N 个，否则取目录之前前 N 个非空段（含封面框表格里的段落）。N 是 `TITLE` 的行数，所以 `TITLE` 的行数要和模板封面的标题行数一致（例如模板封面是“软件全称 V1.0”和“详细设计说明书”两行时，`TITLE` 也写两行）。

## 2. content.py

完整示例见 `assets/example/content.py`。

```python
TITLE = ['XX嵌入式软件', 'V1.0', '详细设计说明书']   # 封面各行
NUMBERED = True                                      # 编号版式；参考版式写 False
FIG = {
    '00': ('flowcharts/00_软件总体结构.png', '软件总体结构图', {'max_h_cm': 14}),  # 第二项：图题 / 替代文字
    '01': ('flowcharts/01_软件运行流程.png', '软件运行流程图'),     # 可选第三项：单图尺寸 max_w_cm / max_h_cm / scale
    's1': ('shots/下行1.png', '下行控制界面', 'shot'),            # 截图：第三项写 'shot'
}
LIKE = None                         # 可选：参考软著路径，等同命令行 --like
FIG_SCALE = 0.85                    # 可选：流程图按 mmdc 原生尺寸的倍数插入（默认 0.85）
FIG_MAX_H_CM = 16.5                 # 可选：流程图限高（默认 16.5 cm）
HEADER_REPLACE = []                 # 用参考软著当模板时填 [('参考软件全称', '本软件全称')]
COVER_FIELDS = {'作者': '……'}       # 可选：模板封面表格“作者:”等右侧空格；只填申请人确认过的真实信息
BLOCKS = [
    ('pb',),                                   # 分页（自带模板的封面后已分页，此处让正文从目录后新起一页）
    ('h1', '软件概述'),                        # 编号版式：h1/h2/h3；参考版式：('h2c', '一：软件概述')、('h2', '功能章节')
    ('p', '本软件运行于……'),
    ('h1', '系统运行要求'),
    ('req', '硬件环境：……'),
    ('h1', '软件总体设计'),
    ('h2', '软件总体结构'),
    ('p', '……详情如{图:00}所示。'),            # {图:key} → 编号版式“图3-1”，参考版式“下图”
    ('fig', '00'),
    ('fields', '具体字段解释如下：', [('上位机通信层：', '包括……')]),
    ('li', 'FUN 0x27：设置过热阈值。'),        # 单条项目符号段（参考件的项目符号样式）
    ('table', [['功能码', '名称', '说明'], ['0x01', '查询版本', '……']], {'widths': [2, 3, 9.6]}),
    ('p', '……', 'keep'),                       # 'keep'：与下一段同页
]
```

- 每张图在 BLOCKS 中只插入一次；FIG 中没被使用的图会给出警告。
- `{图:key}` 引用了不存在或未插入的图时，脚本直接报错。
- 表格第一行为表头（加粗、浅灰底、跨页重复）；`widths` 单位为厘米，可省略。

## 3. 生成与目检

```bash
python3 <skill>/scripts/build_docx.py --content content.py --out out/<全称>_详细设计说明书.docx --auto-toc [--template 模板.docx]
python3 <skill>/scripts/check_ruanzhu.py design out/<全称>_详细设计说明书.docx --name <全称> --version V1.0 --code-lines <源程序量> --pdf out/pdf/<全称>_详细设计说明书.pdf
```

- **样式**：脚本自动识别模板的 heading 1/2/3、TOC 1/2/3、TOC Heading、Hyperlink 和项目符号编号。正文为宋体小四、1.5 倍行距、首行缩进 2 字符，可在 content.py 的 `STYLE` 里改 `font` 和 `sz`（半磅）。
- **编号**：模板的标题样式自带多级编号时，标题文字不加编号；否则脚本在标题前加“3.1 ”这样的文字编号。目录条目始终带编号。
- **目录页码**：`--auto-toc` 用 LibreOffice 渲染 PDF，查出各标题所在页并回填目录，反复执行直到页码稳定。PDF 在输出目录的 `pdf/` 子目录下。Word 与 LibreOffice 的分页可能差一两页，交付时提醒用户在 Word 中右键目录 → 更新域 → 更新整个目录。
- **封面**：封面标题段上的项目符号或编号会被去掉；编号版式下封面行不进入目录。
- **图片**：流程图按 mmdc 原生尺寸的 0.85 倍插入（14px 字在 Word 里约 9 pt，与已获批样例的图面一致），宽不超过版心，高不超过 16.5 cm，不放大；总体结构图建议单图限高 14 cm。图过大时检查给 F05，被推到下一页留下空白时给 P02。缩到 2/3 并量化为 256 色以控制文件体积。截图不量化。
- **目检**：用 `pdftoppm -r 60` 生成缩略图并拼起来看，覆盖封面、目录、正文和几张大图页。标题不能意外折行，目录不能变成斜体，图里的文字要看得清，图题与图在同一页。

## 4. 写回用户文件

- 写回用户目录前，若目标文件已存在，先复制为同目录下的 `<原名>_原版备份.docx`；写回前用 md5 确认原文件在你工作期间没有被改动。
- 目录里有 `~$` 开头的 Word 锁文件，说明用户正开着这个文件：写回后提醒用户在 Word 中关闭它（不要保存，否则会盖掉新版本）再重新打开。用户给的路径本身是 `~$` 锁文件时，改用同名的正式文件。
- 流程图整组替换时，原图目录先复制为 `流程图_原版备份`。
- 交付文件夹里只保留一份定稿；草稿、旧版本和模板副本放到子目录或删除前先问用户，避免提交错版本。

## 5. 重排已有说明书（restyle：正文不动，版式和图样照参考件）

用户说“参考那份软著改格式”“图片简化一下”时，正文文字不改，只换版式和图：

```bash
python3 <skill>/scripts/docx_to_content.py 原说明书.docx --out content.py --media-dir figs_old
# 核对 content.py 的 TITLE（行数与模板封面一致）；把 FIG 的图片路径换成精简后的流程图 PNG
python3 <skill>/scripts/build_docx.py --template 原说明书.docx --like 参考软著.docx --content content.py \
    --out out/<全称>_详细设计说明书.docx --auto-toc
python3 <skill>/scripts/check_ruanzhu.py design out/<全称>_详细设计说明书.docx --name <全称> --version V1.0 --like 参考软著.docx
```

- `docx_to_content.py` 按样式名识别标题，带编号的段落记为 `('li', …)`，图片导出并把紧随的“图 3-1 标题”作为图题，正文里的“图3-1”换成 `{图:key}` 占位。文字中的 `&lt;` 等转义已还原，生成时统一转义，不会出现“&amp;lt;”。
- 以原说明书作模板，可保留它的封面、修订记录和页眉；以参考件作 `--like`，标题、正文、项目符号、图片段、图题和目录都换成参考件的格式。
- 流程图按 flowcharts.md 第 7 节精简后重新渲染，保留原图号和文件名，正文的图号引用就不用改。
- 核对：新旧文档正文字数一致（只差图题）；`check_ruanzhu.py design --like` 的 R01 为 INFO（一致）；逐页看缩略图。

## 6. 照参考件排版（--like）

`build_docx.py --like 参考软著.docx` 从参考件里取出真实段落的格式，生成时逐段套用：

- 一、二、三级标题（含段前分页、样式自带的多级编号）、正文（出现最多的格式）、项目符号段、图片段、图题，以及目录的标题段、各级条目和制表位。
- 参考件有图题时默认 `NUMBERED = True`；一级标题段前分页时，不再另加分页。
- 模板缺少参考件用到的样式或编号定义时自动补入（同名样式沿用模板的 ID）；主题字体与参考件不同时给出提示。
- 参考件正文没有表格时，`('table', …)` 会给出提示：照参考件的写法改成“具体字段解释如下：”加项目符号（`'fields'` 或 `'li'`）。
- 生成后用 `check_ruanzhu.py design --like 参考软著.docx` 逐类比较（R01）。LibreOffice 预览缺少宋体时会用替代字体，说明书不要做等宽字体映射，否则行高变化、页数失真；以 R01 的格式比较为准。
